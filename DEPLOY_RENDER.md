# Deploying BunonBrain on Render

The Blueprint is [render.yaml](render.yaml). This guide covers what it does not:
the external services, the secrets, the PDF data and the computer-vision PC.

## 1. Where each part runs

| Part | Runs on | Why |
|---|---|---|
| Frontend (Next.js) | Render web service `bunonbrain-web` (**free**) | public website |
| API (.NET 10, Docker) | Render web service `bunonbrain-api` (**starter**) + 1 GB disk | public (CV PC and IoT devices call it); the disk keeps uploaded files |
| PDF RAG (FastAPI, Docker) | Render web service `bunonbrain-rag` (**free**) | public URL, but every route except `/health` needs `PYRAG_API_KEY`, which only the API has |
| Database | Supabase (as today) | Postgres + pgvector |
| Vector store | Qdrant Cloud (free 1 GB cluster) | Render has no managed Qdrant, and a self-hosted one needs another service + disk |
| Computer vision | a PC/server inside the factory | it must reach the RTSP cameras / webcams on the factory LAN; CPU-only YOLO on Render is slow and needs a 2 GB plan |
| MQTT broker (optional) | HiveMQ Cloud / EMQX Cloud, or none | Render only accepts HTTP(S) from the internet, not MQTT on 1883/8883 |

```
Browser ──https──> bunonbrain-web ──private network──> bunonbrain-api ──> Supabase
                                                          │   ▲
                              https (X-Rag-Api-Key)       │   │ https (X-Service-Key)
                                                          ▼   │
                                                  bunonbrain-rag ──> Qdrant Cloud, Gemini
                                                              │
                                          Factory PC: computer-vision ──> cameras (RTSP)
```

All three Render services are in **Singapore** (closest to Supabase in Mumbai).

**Cost (budget setup):** API Starter ($7) + 1 GB disk ($0.25) ≈ **$7.25/month**; the frontend,
RAG service and Qdrant Cloud are free. A $50 Render credit lasts about 7 months. Keep the
workspace on the free **Hobby** plan.

Only the API must be paid: free instances sleep after 15 idle minutes (which would stop the
API's background workers) and can't have a disk. The free frontend and RAG service sleep too,
so after a quiet period:
- the first page load takes ~1 minute;
- the first Ask can fail with a timeout (the frontend's `/api` proxy gives up after 30 s while
  the RAG service wakes up); asking again works.

Free instance hours are shared by the workspace (750 h/month), so don't keep both free services
awake 24/7 with an uptime pinger. To remove the wake-ups, set `plan: starter` on
`bunonbrain-web` / `bunonbrain-rag` (+$7 each). If the API restarts with out-of-memory errors,
move it to Standard (2 GB, $25).

## 2. Before you start

1. **Production database (recommended).** Create a separate Supabase project for production
   so test data and the live factory don't mix, and so your local API and the Render API
   don't share the session pooler's **15-client limit**. Use Dashboard → Connect →
   *Session pooler* (port 5432, never 6543) and add `;Maximum Pool Size=10`:
   ```
   Host=aws-0-ap-south-1.pooler.supabase.com;Port=5432;Database=postgres;Username=postgres.<ref>;Password=<pw>;SSL Mode=Require;Trust Server Certificate=true;Maximum Pool Size=10
   ```
   The API creates the `vector` extension, applies migrations and seeds the admin on first start.
   If you reuse the current database instead, also reuse the current `AI_SETTINGS_ENCRYPTION_KEY`.
2. **Qdrant Cloud.** cloud.qdrant.io → create a free cluster (AWS, Asia region) → copy the
   cluster URL (`https://….cloud.qdrant.io:6333`) and an API key.
3. **Gemini key** for the RAG service: aistudio.google.com/app/apikey.
4. **Code on GitHub.** Commit `render.yaml` and push. Render deploys from one branch; merge to
   `main` or pick `frontend-integration-and-admin-roles` when creating the Blueprint.

## 3. Create the Blueprint

Render dashboard → **New → Blueprint** → connect the GitHub repo → choose the branch.
Render reads `render.yaml` and asks for every `sync: false` value:

| Service | Key | Value |
|---|---|---|
| api | `BUNONBRAIN_DB` | connection string from step 2.1 |
| api | `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` | first Super Admin (strong password) |
| api | `AI_SETTINGS_ENCRYPTION_KEY` | new DB: `openssl rand -base64 32`; same DB: copy from local `.env` |
| api | `CORS_ORIGINS`, `PUBLIC_APP_URL` | `https://bunonbrain-web.onrender.com` |
| api | `LLM_MODEL`, `LLM_API_KEY` | same as local `.env` |
| rag | `GOOGLE_API_KEY` | Gemini key |
| rag | `PYRAG_QDRANT_URL`, `PYRAG_QDRANT_API_KEY` | from Qdrant Cloud |

`JWT_SIGNING_KEY`, `CV_SERVICE_KEY` and `PYRAG_API_KEY` are generated by Render, and the API
gets the RAG key automatically.

First build takes ~10 minutes (the .NET image is the slowest).

## 4. Check the generated addresses

- If a service name was already taken, Render adds a suffix (e.g. `bunonbrain-web-ab12.onrender.com`).
  Fix `CORS_ORIGINS` / `PUBLIC_APP_URL` (frontend URL) and `PYRAG_SERVICE_URL` (RAG URL) on the API.
- Open `bunonbrain-api` → **Connect → Internal** and confirm the private address is
  `bunonbrain-api:8080`. If not, fix `NEXT_PUBLIC_API_URL` + `DOTNET_API_URL` on the frontend.
  The frontend bakes them in at build time, so use **Manual Deploy → Clear build cache & deploy**
  after changing them.

## 5. Load the PDFs into Qdrant Cloud

The new Qdrant cluster is empty, and the old local vectors were made with a different
embedding model (huggingface, 384-dim), so re-ingest with Gemini embeddings. From your PC
(PowerShell, in `rag/`; real environment variables win over `.env`):

```powershell
$env:PYRAG_EMBEDDING_PROVIDER = "google"
$env:PYRAG_EMBEDDING_MODEL    = ""
$env:PYRAG_EMBEDDING_DIM      = ""
$env:PYRAG_QDRANT_URL         = "https://<cluster>.cloud.qdrant.io:6333"
$env:PYRAG_QDRANT_API_KEY     = "<qdrant key>"
$env:PYRAG_QDRANT_PATH        = ""
python ingest.py --pdf data/<your-file>.pdf --recreate
```

Run it once per PDF (`--recreate` only for the first one). Then ask a question in the app.

## 6. Computer vision in the factory

On a PC in the factory network (Windows/Linux, Python 3.11 or Docker), in `computer-vision/.env`:

```
CV_BACKEND_URL=https://bunonbrain-api.onrender.com
CV_BACKEND_SERVICE_KEY=<value of CV_SERVICE_KEY from the API's Environment tab>
CV_API_KEY=<new random 32+ chars>
CV_ENABLE_PREVIEW=false
CV_ALLOW_SOURCE_OVERRIDE=false
```

Download the weights (`python scripts/download_model.py`) and start it as described in
`computer-vision/README.md`. It only makes outgoing HTTPS calls to the API, so no port has to be
opened on the factory router. Set it to start with the PC (Task Scheduler / systemd, or
`docker run --restart unless-stopped`).

## 7. IoT / MQTT (optional)

- HTTP device ingestion works as-is against `https://bunonbrain-api.onrender.com`.
- For MQTT, use a hosted broker with TLS (HiveMQ Cloud / EMQX Cloud free tier) and set on the API:
  `Iot__Mqtt__Enabled=true`, `Iot__Mqtt__Host`, `Iot__Mqtt__Port=8883`, `Iot__Mqtt__UseTls=true`,
  `Iot__Mqtt__Username`, `Iot__Mqtt__Password`. Update `deploy/esp32` to the same broker.

## 8. Check it works

1. `https://bunonbrain-api.onrender.com/health` → `Healthy`.
2. Open the frontend, sign in with the seeded admin.
3. Upload a QC image and a worker photo, then **Manual Deploy** the API and check they are still there (the disk works).
4. Ask BunonBrain a question about an ingested PDF (RAG + Qdrant work).
5. Overview page updates live (SignalR through the frontend).
6. Start a camera from the CV PC: events show up in Monitoring.

## 9. Things to know

- **Disk permissions.** The API container runs as a non-root user (uid 1001). If uploads fail with
  "Permission denied" under `/app/App_Data`, the mounted disk is owned by root: change the
  Dockerfile so the runtime stage starts as root, runs `chown -R app:app /app/App_Data`, then drops
  to `app` (for example with `gosu`).
- **Deploys with a disk** stop the old API before starting the new one: ~30–60 s downtime per deploy.
- **Self-registration** is on by default: anyone can create an account (no role until an admin
  grants one). Set `ALLOW_SELF_REGISTRATION=false` on the API to stop that.
- **Password-reset email** needs `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM`.
- **Long requests** through the frontend's `/api` proxy time out after 30 s (Next.js default),
  same as locally.
- **Custom domain:** Settings → Custom Domains on `bunonbrain-web` (and on `bunonbrain-api` if
  the CV PC/devices should use it); then update `CORS_ORIGINS` and `PUBLIC_APP_URL`.
- **Never** put real values into `render.yaml` or commit `.env`.
